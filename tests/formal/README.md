# QQ 机器人形式化验证范围

优先为同时满足两个条件的流程建模：事件顺序会改变结果，且错误会导致越权、重复外发、旧状态复活或会话错绑。可用一张输入输出表或少量固定顺序覆盖的功能，直接写回归测试。模型以插件能控制的状态为边界；宿主接口和 QQ 协议通过集成测试核验。

## 已建模

| 核心流程 | 要守住的规则 |
| --- | --- |
| [手动发送与账本](qq-delivery/README.md) | 一次操作最多提交一次；撤权后不开始发送；账本缺失、清空和重启不能让旧操作复活。 |
| [配对码认领与撤权](qq-pairing/README.md) | 旧码不能重新加白；成员和配对回执分步落盘时，重载或回滚配对文件不能复活已撤销身份。 |
| [Session 切换](qq-session-switch/README.md) | Web 新建、QQ /new、入站恢复和网关重载交错时，只有当前运行实例能提交匹配预期的绑定。 |
| [流式回复与静态回退](qq-stream-fallback/README.md) | 流式与静态共用回复身份；首帧结果未知时不能另开消息；晚到回执不能解除防重。 |
| [审批与提问的请求生命周期](qq-interaction-lifecycle/README.md) | 取消、超时、换 Session 或卸载后，迟到的回执和旧卡片不能恢复或完成请求。 |
| [入站归属与出站准入](qq-origin-admission/README.md) | 即使 OpenID 相同，也只能由原机器人认领和发送。混合来源、撤权和绑定失效均阻止后续请求。 |

## 接下来建模

| 优先级 | 核心边界 | 最小模型与不变量 |
| --- | --- | --- |
| 1 | 自定义工具策略的生效与继承 | 一个会话、一个子 Agent、一次配置保存。交错工具描述、执行、撤权、Agent 更换和守卫安装失败。所执行工具始终受当前 QQ 工具范围与原生权限共同约束；旧配置或旧 Agent 回调不能扩大权限。宿主的工具和 PTC 契约仍用集成测试核验。 |

## 保持回归与集成测试

| 模块 | 验证方式 |
| --- | --- |
| 多机器人启停、凭据换绑、扫码 | 用延迟回调和实际 Host 验证停 A 不影响 B、旧回调不能接管新绑定。已由发送、入站归属和 Session 模型覆盖的权限边界无需重复建模。 |
| 服务范围、命令白名单、配置与模型选择 | 用权限表驱动测试覆盖群聊、私聊、命令与回调；用保存后读回、版本冲突和真实模型路由验证生效。配对与撤销的跨重启部分已有模型。 |
| 文件、图片、引用、分片和回复窗口 | 用实际 SDK 请求检查上传前后的授权、文件路径和目标隔离、引用映射、限流和过期。外发前撤权纳入入站归属模型，媒体类型和协议差异留给夹具。 |
| 流水、会话树、UI 与呈现 | 用持久化回归及浏览器验证分页、归属、状态更新、明暗主题和交互。流水状态来源是投递结果，模型在投递边界检查。 |
| 提示词、命令与答案解析、默认值和文本格式 | 用参数化测试检查输入输出，覆盖异常值、旧格式与作用域。 |

从 [测试指南](../../TESTING.md#形式化检查)运行当前模型和负对照。
