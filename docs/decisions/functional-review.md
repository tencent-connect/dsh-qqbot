# QQ Bot 功能、简化与说明审查

日期：2026-10-31。范围为 QQ 插件全部用户流程，承接[原生组件一致性审查](ui-consistency-review.md)。审查为只读检查，不涉及宿主改动。

> 历史审查快照：下文的问题、源码路径与行号描述审查当时的实现；部分文件现已删除或拆分，因此旧源码位置保留为文本引用。当前设置与记录行为见[默认配置与消息记录](../guides/settings-and-message-records.md)，其中补充提示词和人设已改为每步现读，记录默认全部保留并手动清空。

审查基于 QQ 插件源码与浏览器实现核对。

## 结论与优先级

先修实际行为与权限编辑错误，再删除无效选项，最后统一原生控件和说明。账号、QQ对话、原生Session属于不同范围，保留入口，但同一种操作共用表单及行为。原生主聊天、群共享/私聊独立、显式发送与现有工具守卫继续保留。

### 已确认需要修复

| 优先顺序 | 触发与实际结果 | 来源 | 证据与最小修正 |
| --- | --- | --- | --- |
| 1 | v1草稿未保存后关闭，另一处v2撤销工具；重开旧草稿却拿v2作基线，确认会重新提交旧授权且无冲突提示 | `src/client/conversation-policy.ts:35`、`src/client/conversation-policy.ts:183` | 实际组件配离线hooks替身复现 read=allow、expectedVersion=2。缓存草稿同时保存原基线及版本；只有明确重新载入才能更新基线。 |

此外，所有者未加载时被显示为0并可打开空编辑器，策略输入在保存期间仍可改，详见上一轮审查。前者的故障状态尚未做浏览器注入，后者未证实丢失草稿，不能扩大为已发生的数据丢失。

### 行为本身可保留，但描述错误

- `/preset reset`实际创建新Session，帮助却承诺保留当前上下文：`src/commands/help.ts:49`与`src/session/session-manager.ts:350`。旧历史仍在，不等于新会话继续携带旧上下文。
- `processingTimeoutMs`目前覆盖SDK入站处理，不能宣称是原生Agent整轮生成的超时上限。原生输入确认持久化后enqueue已返回，SDK watchdog随next结束；没有对应的Agent取消连接。该项为静态链路发现，未跑计时场景。
- 在当前工作区重新选择相同工作区，服务按无操作处理，但按钮仍承诺新建。应禁用当前项，或统一“切换并新建”的实际语义。
- `/bot-status`与`/bot-version`主要读热缓存，重启/闲置回收后的“无活跃会话/默认模型”不代表持久会话不存在。应恢复读取或明确区分缓存状态与当前QQ映射。

| 默认权限、执行沙箱、允许权限三套分散控件 | 用户难以判断哪个控制当前会话，且有不可保存组合 | 保留原生输入区的当前权限；QQ设置区分新会话默认值与允许上限，并从同一有效状态派生。 |

## 应补齐的说明

| 入口/原词 | 应明确的意义或建议文案 |
| --- | --- |
| 全局“群聊仅回复@” | “新发现群的初始回复规则。已有群请在对话设置修改。”它在首次发现建policy时复制，不是实时总开关，也不因/new重新复制。 |
| “近期背景” | “临时缓存收到的近期消息，不保存完整群记录，重启后未使用的缓存会丢失。”已被某轮采用的背景仍在原生Session中。 |
| “群记录＋按需取用” | “保存实际收到且获准记录的消息。模型查询还需授权qqbot_group_history；网页查询不启动模型。”不能让模式选择暗含工具授权。 |
| “停止接收QQ消息” | 更接近“停用此QQ对话”。说明接收、自动回复、QQ发送及相关工具受限，发现身份与DSH历史仍保留；不意味着QQ平台停止推送事件。 |
| 模型/预设/角色保存 | 写清作用范围及生效时间。当前Session模型保留上下文；更换预设开新Session；角色在新Session生效；默认值不等于覆盖所有现有对话授权。 |
| “历史回答可发送” | 实际只允许当前QQ Session内符合条件的已完成回答；旧Session按钮被隐藏。首版修文案，不擅自扩大转发范围。 |
| “发送成功/失败” | “QQ接口接受x/y段”不等于已送达/已读。失败或未知可能已有部分分段接受；先核对QQ，未知不自动重发。 |
| “保留7天” | 指插件群记录文件的期限；原生Session、已选背景、请求账本及投递记录可能仍有内容。换新不等于删除历史，也不承诺统一清除全部副本。 |
| “解绑” | 清除本机凭据并重载，不删除会话历史，不等于移出QQ群或撤销QQ平台侧关系。 |
| “重新连接/右侧运行概览” | 对应动作若只是GET状态应叫重试读取；当前连接状态在QQ左栏，原“右侧运行概览”指向已不存在区域。 |
| 私聊中的“本群/群记录/群聊提示词” | 使用“此对话/补充指令”，仅群聊显示群平台能力提示。 |
| 工作区修改 | QQ菜单会切换QQ当前会话与默认工作区；不要把所有原生导航动作都描述成修改QQ路由。完整目录留在详情，正常界面使用公共显示名。 |

每个设置至少说明作用对象、生效时间、继承来源、依赖条件和对历史的影响。仅展示技术字段名不足以让用户预判结果。

## 保留的可靠能力与边界

群共享当前会话、私聊独立、原生主聊天、显式发送、未知结果不自动重试继续保留。现有针对控制者/审批者分离、跨群拒绝、资源先校验、审批后撤权重查的测试通过；本轮未发现可确认的底层权限绕过。

未触发的消息不伪装原生日志。仅能使用平台实际推送的消息。native只读遵循DSH语义，不提供任意读取的目录隔离。普通工作区树仍可能列出QQ Session是宿主公开接口限制，不能靠CSS或伪造归档消除。

## 建议实施顺序

1. 修旧草稿版本、自动换新预约、权限/沙箱配对和准入部分失败；每项加对应入口/组件回归。
2. 移除无效设置的当前入口，统一默认值、上下文、发送及命令描述；修发送记录刷新与终态反馈。
3. 按已选方向统一10处下拉、工作区显示名、弹层键盘、普通表单；相同行为共用表单，账号/对话/群权限范围保持清楚。

这几批应分别可验收，避免把权限行为修复藏在纯视觉改动里。无需新增宿主改动、服务部署或功能模块。

## 验证与证据

- Session/runtime/commands/model针对性测试：13个文件144项通过。
- policy/client/auth/workbench/approval针对性测试：5个文件68项通过。两组存在交集，不合计为212个独立测试。
- 主代理重跑自动换新离线gate对照、实际组件旧草稿探针，以及纯策略校验/真实路由配替身service的故障探针。证明当前缺陷，不能当作修复后验收。
- 无Host启动、真实QQ消息、模型调用、浏览器故障注入或实现修改。源码与既有测试不能替代未来真实端到端验收。
- 测试执行器曾自动补写包管理元数据，已恢复，并与上一份已打包的package.json逐字比对一致；无残留实现变更。

探针脚本（functional-session-probe、permission-review-probe、permission-draft-review）使用独立 vitest 配置，不进入普通测试发现范围。

已排除的假设：裸PermissionPresetService默认表不含read-only，不代表默认Web部署缺该能力；stock base bundle明确配置read-only。不能把这个组件级默认值探针列为默认安装故障。
